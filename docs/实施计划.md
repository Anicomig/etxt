## 前置决策（阻塞实现）

实现前必须确定以下 4 项，否则代码结构会返工：

| # | 决策项 | 选项 | 影响 |
|---|---|---|---|
| D1 | 触发方式 | `.etxt` 专用扩展名 / 保留 `.txt` + 右键 | 决定注册表写入内容和是否影响现有 txt |
| D2 | 编辑器 | 内置 tkinter 编辑器 / Typora / 系统记事本 | 决定泄漏清理逻辑复杂度 |
| D3 | 单文件规模 | <1MB / 10MB / 更大 | 决定是否流式加解密 |
| D4 | 密码模型 | 每文件独立密码 / 一个密码管多文件 | 决定是否需要密钥库 |

**默认假设**（用户未指定时按此实现）：
- D1 = `.etxt` 专用扩展名
- D2 = 内置 tkinter 编辑器（最安全）
- D3 = 单文件 < 10MB，一次性读入内存
- D4 = 每文件独立密码

## 文件结构

```
etxt/
├── 调研报告.md                  # 已完成
├── 实施计划.md                  # 本文件
├── etxt/
│   ├── __init__.py
│   ├── crypto.py               # 加密格式：scrypt + AES-GCM，纯函数，可单测
│   ├── store.py                # 文件读写：原子写回、临时文件、安全删除
│   ├── ui.py                   # tkinter 密码框 + 内置编辑器
│   ├── cli.py                  # 命令行入口：加密/解密/查看
│   ├── app.py                  # 主流程编排：双击触发的入口
│   └── assoc.py                # 注册表关联安装/卸载
├── tests/
│   ├── test_crypto.py
│   ├── test_store.py
│   └── test_roundtrip.py
├── tools/
│   └── make_shortcut.py        # 生成桌面快捷方式（可选）
└── README.md                   # 使用说明
```

**设计原则**：
- `crypto.py` 和 `store.py` 是**纯逻辑，无 UI 依赖**，可以完全脱离 GUI 测试
- `ui.py` 只负责交互，不碰加密逻辑
- `app.py` 负责编排，是唯一知道"完整流程"的地方
- 这样即使将来换编辑器，只需改 `ui.py` 和 `app.py`

## 任务分解

### Task 1: 加密格式核心

**文件**：`etxt/crypto.py`、`tests/test_crypto.py`

**格式定义**：
```
偏移  长度   内容
0     6     magic = b"ETXT1\0"
6     16    salt (scrypt)
22    12    nonce (GCM)
34    N     密文
34+N  16    GCM tag（cryptography 的 AESGCM.encrypt 已包含在返回值里）
```

**步骤**：

- [ ] 1.1 写失败测试 `test_roundtrip`：加密再解密应得原文
- [ ] 1.2 运行测试，确认 `ImportError` 或 `AttributeError` 失败
- [ ] 1.3 实现 `derive_key(password: str, salt: bytes) -> bytes`，用 `hashlib.scrypt(n=2**15, r=8, p=1, dklen=32)`
- [ ] 1.4 实现 `encrypt(plaintext: bytes, password: str, aad: bytes) -> bytes`
- [ ] 1.5 实现 `decrypt(blob: bytes, password: str, aad: bytes) -> bytes`
- [ ] 1.6 运行测试，确认通过
- [ ] 1.7 写测试 `test_wrong_password`：错误密码应抛 `WrongPassword`
- [ ] 1.8 写测试 `test_tamper_detected`：改密文 1 字节应抛 `WrongPassword`（或 `Corrupt`）
- [ ] 1.9 写测试 `test_aad_binding`：用不同 aad 解密应失败
- [ ] 1.10 写测试 `test_nonce_uniqueness`：连续加密两次，密文应不同
- [ ] 1.11 运行全部测试，确认通过

**验收标准**：
- 所有测试通过
- 错误密码和文件损坏都归类为 `WrongPassword`（不向用户暴露具体原因，避免 oracle）
- 两次加密同一内容产生不同密文

## 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 用户忘记密码 → 文件永久丢失 | 中 | README 醒目警告；不提供后门 |
| 加解密过程中断电 → 文件损坏 | 低 | 原子写回（`os.replace`），原文件保留到新文件写完 |
| 临时明文被其他程序读取 | 低 | 随机文件名 + 严格 ACL + 用后即删 |
| 双击关联被其他软件抢走 | 中 | 提供 `assoc.py install` 一键重装 |
| Python 升级导致路径失效 | 低 | 注册表里存绝对路径；提供重装命令 |
