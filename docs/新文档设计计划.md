## 一、技术前提（已实测）

### 1.1 右键菜单必须换注册位置

**实测发现**：`.md` 的 ProgId 是 `JeffBox.Markdown`，**不是** `txtfile`。

所以当前挂在 `txtfile\shell` 下的菜单**只对 .txt 生效，对 .md 无效**。

**正确做法**：改用 `SystemFileAssociations`，它对所有指定扩展名生效，且**不依赖该扩展名当前关联到哪个程序**。

```
HKCU\Software\Classes\SystemFileAssociations\.txt\shell\EtxtEncrypt
HKCU\Software\Classes\SystemFileAssociations\.md\shell\EtxtEncrypt
    (Default) = "加密为 etxt"
    \command
        (Default) = "<exe>" --encrypt "%1"
```

**已实测验证**（2026-11-12）：

注册后通过 Shell COM 枚举真实右键菜单，两个扩展名都出现了菜单项：

```
--- 测试.txt ---
  &Open / 编辑 / 打印 / 询问 Copilot / 加密为 etxt (probe) / ...

--- 测试.md ---
  &Open / 询问 Copilot / 加密为 etxt (probe) / ...
```

说明 `SystemFileAssociations` 方案确实能同时覆盖 `.txt` 和 `.md`，且不需要改默认程序。

### 1.2 默认保存位置

实测 `SHGetKnownFolderPath(FOLDERID_Documents)` 返回：

```
F:\Documents
```

注意本机 Documents 被重定向到 F 盘，所以**不能硬编码** `%USERPROFILE%\Documents`，必须用 API 取。

### 1.3 文本 / 二进制判定

「改名文件引导」需要区分「明文」和「二进制」，实测判定逻辑：

```python
def looks_like_text(data: bytes) -> bool:
    if not data:
        return True                      # 空文件算文本
    if b"\x00" in data[:4096]:
        return False                     # 含 NUL 视为二进制
    try:
        data[:8192].decode("utf-8")
        return True
    except UnicodeDecodeError:
        try:
            data[:8192].decode("gbk")
            return True
        except UnicodeDecodeError:
            return False
```

实测结果：

| 输入 | 判定 |
|---|---|
| 纯文本 / CRLF / 空文件 | text=True |
| 二进制 / PNG 头 / 密文 | text=False |

这个判定是「改名引导」能正确触发的前提。

## 二、双击 exe 的行为

### 2.1 目标语义

```
双击 exe
  ├─ 检查关联是否完整
  │    ├─ 未安装 / 指向旧路径 / 缺右键菜单
  │    │     → 静默修复（不弹提示）
  │    └─ 完整 → 跳过
  └─ 始终进入「新建加密文件」流程
```

**关键变化**：安装不再弹「已关联」提示。用户双击 exe 的意图就是「新建」，不该被打断。

### 2.2 「关联完整」的判定

需要同时满足：

| 检查项 | 判定 |
|---|---|
| `.etxt` 扩展名指向我们的 ProgId | `HKCU\Software\Classes\.etxt` = `Etxt.EncryptedText` |
| 打开命令指向**当前** exe | `points_to(_exe_path())` |
| 右键菜单已注册 | `.txt` 和 `.md` 的 `SystemFileAssociations` 都存在 |
| 图标已设 | `DefaultIcon` 存在 |

任一项不满足 → 静默重装（不弹窗），然后继续新建。

> 这样用户把程序挪了位置、或者更新了版本，双击 exe 会自动修好，不需要手动操作。

## 三、新建流程（含保存位置选择）

### 3.1 流程图

```
双击 exe / 菜单新建
  ↓
[保存位置弹窗]
  ┌─────────────────────────────────────┐
  │  新建加密文件                        │
  │                                      │
  │  文件名  [新建加密文本.etxt      ]   │
  │                                      │
  │  保存到                              │
  │  ┌────────────────────────────────┐ │
  │  │ F:\Documents    │ │  ← 默认
  │  └────────────────────────────────┘ │
  │  [浏览…]                             │
  │                                      │
  │  ○ 使用默认位置                      │
  │  ● 自定义位置                        │
  │                                      │
  │  [取消]                    [下一步]  │
  └─────────────────────────────────────┘
  ↓
[设置密码 + 恢复码]（复用现有 AuthDialog setup 视图）
  ↓
[编辑器]
```

### 3.2 保存位置弹窗设计要点

- **默认位置**：`Documents` 目录（用 API 取，不硬编码）
- **文件名**：预填「新建加密文本.etxt」，自动选中主名部分方便直接改
- **两个单选**：默认位置 / 自定义位置
- **浏览按钮**：只有选「自定义」时可用
- **路径校验**：目录不存在、无写权限时，「下一步」禁用并提示
- **同名文件已存在**：提示是否覆盖（默认不覆盖，要求改名）

### 3.3 与「首次安装」的衔接

未安装时：
1. 静默安装（无提示）
2. 安装失败才弹错误
3. 成功后**直接进入新建流程**，不插入任何「已关联」提示

## 四、改名文件的引导

### 4.1 触发条件

```
双击 .etxt 文件
  ↓
读文件头
  ├─ magic == "ETXT2\0"  → 正常解锁流程
  ├─ magic == "ETXT1\0"  → 旧版兼容流程
  └─ 其他
       ├─ 内容可解码为文本 → 弹「这个文件还没有加密」
       └─ 二进制内容 → 报「不是加密文件」
```

### 4.2 引导弹窗

```
┌──────────────────────────────────────┐
│  这个文件还没有加密                   │
│                                       │
│  笔记.etxt 的内容仍是明文。           │
│                                       │
│              [加密后打开]  [取消]     │
└──────────────────────────────────────┘
```

两个按钮（按 D1）。

- **加密后打开** → 走设置密码流程 → 原地加密 → 打开编辑器
- **取消** → 退出，不改动文件

### 4.3 「加密后打开」之后的提示（按 D4）

加密完成、编辑器打开**之前**，立即弹：

```
┌────────────────────────────────────────┐
│  加密完成                               │
│                                         │
│  已加密：F:\...\笔记.etxt              │
│                                         │
│  恢复码：kMBF-Aqj1-B9yb-qkh6           │
│  请立即抄下，忘记密码时只能靠它。       │
│                                         │
│  ☐ 删除原文件笔记.txt（明文）          │
│                                         │
│                          [确定]         │
└────────────────────────────────────────┘
```

注意：**原地加密时原文件就是目标文件本身**，没有「另一份明文」可删。所以复选项只在**右键加密**（生成新文件）场景出现。

> 这里需要区分两种场景：
> - **原地加密**（改名后双击）：文件已经是 `.etxt`，加密后原地覆盖，无残留明文 → **不显示删除复选**
> - **右键加密**（`笔记.txt` → `笔记.etxt`）：产生新文件，原 `.txt` 还在 → **显示删除复选**

### 4.4 原地加密的安全性

必须保证失败不损坏原文件：

```
1. 读原文（明文）
2. 加密到临时文件（同目录，随机名）
3. fsync
4. os.replace(临时文件, 原路径)   ← 原子替换
5. 失败则删除临时文件，原文件不动
```

## 六、.md 支持（按 D8：纯文本显示）

### 6.1 原则

`.md` 在编辑器里**按纯文本显示**，不做任何 Markdown 渲染。

这与现有编辑器的行为一致（它本来就是纯文本编辑器），所以**无需改编辑器**。

### 6.2 需要改的地方

| 位置 | 改动 |
|---|---|
| 右键菜单 | 用 `SystemFileAssociations` 覆盖 `.md`（Task 2） |
| `--encrypt` 参数 | 已支持任意路径，**无需改** —— 它用 `with_suffix(".etxt")` 生成目标，`.md` 同样适用 |
| 改名引导 | 已支持任意扩展名，**无需改** |
| 打开对话框的文件类型过滤 | 加 `*.md` |

注意 `encrypt_plain_file` 里的目标路径逻辑：

```python
dst = src.with_suffix(".etxt")     # 笔记.md → 笔记.etxt
```

这个对 `.md` 直接可用，不需要额外分支。

### 6.3 不做的

- 不做 Markdown 语法高亮
- 不做预览
- 不做 .md 的默认程序关联（不抢 Typora）

## 九、边界情况

| 情况 | 处理 |
|---|---|
| 双击 exe 但无写权限装注册表 | 弹错误，说明需要什么权限 |
| 保存位置目录不存在 | 「下一步」禁用 + 提示 |
| 保存位置无写权限 | 同上 |
| 目标文件已存在 | 提示改文件名，不覆盖 |
| 原地加密时磁盘满 | 临时文件写失败，原文件不动，报错 |
| 改名文件是二进制 | 报「不是加密文件」，不走引导 |
| 批量加密中途失败 | 已成功的保留，失败的报告，不整体回滚 |
| `.md` 文件很大（>10MB） | 一次性读入内存，暂不做流式 |

## 十、不做什么

- **不做 Markdown 渲染**（D8 明确）
- **不抢 `.md` 的默认程序**（不干扰 Typora）
- **不做自动删除原文件**（默认保留，需用户勾选）
- **不做云同步 / 多设备密钥**
- **不做流式加解密**（单文件 < 10MB 场景）
- **不改 `.txt` 的双击行为**（右键菜单不影响默认程序）
